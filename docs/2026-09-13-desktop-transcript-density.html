规则（方案 A）

  1. 一行过程条 = 一轮的 thinking + 工具卡 + 中间说明，位置在原处（用户气泡之后、答案之前）。折叠态一行，展开态就是今天的渲染原样。
  2. 恒显：① 该轮最后一段正文；② 失败/被拒的步骤（不藏进折叠里，红了就露出来）；③ 权限卡、提问卡（阻塞项）；④ 已停止 / 出错标记。
  3. 运行中是实时条：脉冲点 + 「正在 <工具> · <目标>」+ 第 N 步 + 用时递增；结束后收成摘要（步数 / 耗时 / 工具构成 / 失败数）。
  4. 档位（偏好，存 desktop_ui.json）：简洁 / 平衡（默认）/ 详细。详细 = 现状，给"想看全程"的时刻留出口。
  5. 展开状态是展示态，不入库：重开会话按档位默认，手动展开过的那一轮在本次会话内记住。

要注意的

  1. smoke 里大量断言是「工具卡存在/数量」（.tool-status）：折叠后默认不可见 → 场景要先展开，或改断言过程条。这是本次改动最大的一块连带成本。
  2. 折叠会收缩高度：现有"跟随底部"是盯内容盒子的 ResizeObserver，生长没问题，收缩要确认不抖。
  3. 中途展开/收起发生在流式期间时，别让滚动位置跳；用户手动展开过的那一轮，轮末不要自动收起。
  4. 过程条的工具构成由 parts 直接算（确定性、不额外请求）；别用 LLM 生成摘要——那会多一次调用，也会在重启后与历史不一致。
