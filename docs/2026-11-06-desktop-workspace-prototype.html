D

删除会话时的勾选

只在这个会话确实有自己的 worktree 时出现，默认不勾；工作树有未提交改动就整条拒绝。

删除会话「补单测」？
这个会话的 1 个定时任务也会一并删除。
同时删掉它的 worktree 目录 ~/work/my-repo-wt/tachi-fix-skill-test 分支 tachi/fix-skill-test 会留着；有未提交的改动就删不了
此操作不可恢复。
同时删掉它的 worktree 目录 有 3 个未提交的改动，先提交（或取消勾选）再删

F

行为对照：每个动作动了谁

你做的事变化的不变的
在项目里新建会话（＋） 新会话拿到一份项目当前目录的副本 项目、其他会话
改项目的主目录 / 附加目录 项目记录本身；之后新建的会话 所有已经存在的会话
在会话面板里改目录 只有这个会话；它变成「已改动」 项目、其他会话
点「恢复为项目当前工作区」 这个会话的目录回到项目现在那份 文件、git 状态（只换 agent 看哪个目录）
建 worktree 这个会话的主目录换成新目录 + 新分支；侧栏出现分支标记 会话历史、项目、主目录的文件
删项目 侧栏少一个分组；成员变成「无项目」 每个会话的目录（本来就已经是各自的）

还没定的事

这几件需要你拍板，我没写进稿子里：
  1. worktree 的回收。会话删掉时，那个目录要不要一起删？我倾向不删，只在面板里说「这个目录是 tachi 建的」并给一个手动「移除 worktree」。
  2. 「已改动」那个点要不要上侧栏。稿子里上了；如果嫌吵，只留分支标记，改动只在面板里体现。
  3. 新建时就能选 worktree 吗。稿子只在会话面板里建（建完再决定隔离更常见，＋ 保持一键）。要的话可以在 ＋ 上挂右键菜单「在 worktree 里新建」。
  4. 会话能不能换到另一个项目。稿子留了「挂到别的项目」，但没细设计。
