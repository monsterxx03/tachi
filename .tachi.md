# Tachi — Development Conventions (Agent Guide)

## Splits — read on demand

The conventions that hold anywhere in the repo are here; anything area-specific lives in a handbook
beside this file and is read only when it matters — a new lesson goes into the handbook it belongs to,
not here.

**What kind of document you are writing decides where it goes.** This file and `docs/agents/` describe how
things ARE and must be kept true in the same turn. Dated docs under `docs/` are feature DESIGN documents —
a design at a point in time, allowed to go stale — and are not referenced from here.

- **`docs/agents/desktop.md`** — read it **before changing anything under `desktop/`**: the smoke suite,
  build & signing, the Wails backend (bindings, session paths, open/reveal), the frontend's ownership of
  transcript / sidebar / events / composer / panel width, and the MCP client & authorization path.
  (The badge path — `desktop/link/`, `desktop/badge.go`, `desktop/stt/` — has its own handbook below.)
- **`docs/agents/permission.md`** — read it **before touching `agent/permission/` (incl. `jevask/`,
  `jevfiles/`, `paths.go`), `agent/agent_permission*.go`, `permissions.bash` or `permissions.files`, before
  adding a tool that raises an ask or touches a path, and before believing any judgment threshold**: rule
  order, the ask path, the two judgment gates (commands and file tools), the τ discipline, and which trees
  contribute rules. (The desktop's tree resolver and permission cards are in `desktop.md`.)
- **`docs/agents/badge.md`** — read it **before touching the badge path** (`desktop/link/`, `desktop/badge.go`,
  `desktop/stt/`) or **when the badge screen and the app disagree**: the BLE transport traps nobody can guess
  from the code, the voice/STT path (assets, degradation, what the screen says on failure), and where the
  device-side repository, its own gate, and the NVS-preserving flash live.
- **`docs/agents/mcp.md`** — read it **before touching `agent/mcp/`, the search tool (`agent/tools/mcp_tool_search.go`)
  or the deferred-tools reminder**: the pool/reminder invariants, the search's two halves and the `server`
  narrowing, the result payload, and the schema trap that can kill a whole request.
- **`docs/agents/prompt-cache.md`** — read it **when a cache hit rate drops** (the user's or your own) or a
  restart looks expensive, and before changing anything that shapes a request's prefix: where the numbers
  live, how to read the breakpoint, and what may legitimately break the prefix (a tool-list change is
  structural; a reminder-block rendering change is not).
- **`docs/agents/jev.md`** — read it **before calling `pkg/jev`, before moving a call site onto it, and
  before trusting any threshold it produced**: whether a call site is Jev-shaped at all, what every gate
  needs (degraded path, pinned model, catch-all option), and the traps — register beating language, silent
  failure on non-text state, and why a threshold is never a fact you can copy.
- **`docs/agents/channel.md`** — read it **before changing anything under `channel/`**: the one `Manager`
  and its `buildHandler`, the per-thread agent pool and the ONE lock rule (no guard taken while holding
  another — the nesting is an ABBA hang), and whisper routing.
- **`docs/agents/session-store.md`** — read it **before touching `session/store.go` or anything that reads
  the session list**: what is memoized and what must not be, and why `meta.json` is written atomically.
- **`docs/agents/checkpoints.md`** — read it **before touching `agent/checkpoint/`, a workspace-root
  resolution, or the compaction path**: a root's identity is its path, and a turn's binding is session-scoped.
- **`docs/agents/itest.md`** — read it **before adding or editing a spec under `itest/`, or when one fails
  only on a loaded runner**: the suites, what a wait may anchor on, and the harness's caching rules.

Each handbook is an OUTLINE — one bullet per invariant, the mechanism living in the code it is about — and
its top table says which section to read when. Read that section, not the whole file.

## Code Organization
- Reuse `pkg/` before writing anything new (`logger`, `strutil`, `httpx`, `fileutil`, `container`, `shutil`, …); never re-implement existing capability
- Business-agnostic logic goes into the matching `pkg/`, not inline in business code

## Context Passing
- Pass `context.Context` only when it is used (logging, cancellation, ctx values). No decorative params.

## Quality Assurance
- `make lint` must pass before ending a turn; disable a rule explicitly when it is meaningless for the code
- No magic values: named constants, defined once
- Readability first: refactor instead of piling on; ask before large changes

## Commits
- **Never commit unless the user asks.** Finish the work, run the checks (`make lint`, tests), then report — list the changed files and, if useful, a suggested commit message, but leave git untouched. Commit timing and granularity are the user's call.
- **Never `git add -A`/`git add .`**: a neighbouring session may have unrelated work in the tree. Stage the files you changed, by name.
- **Nothing in a commit may carry an internal product or vendor name, and the hooks enforce it.** `.git/hooks/pre-commit` scans the staged ADDED lines and `commit-msg` the message against a word list (the vendor's name and its internal products); a hit aborts the commit. A fixture, a comment or a doc example therefore takes a neutral name (`github`, `alpha`) — never a server name copied out of this session's own deferred-tools reminder, which is runtime state and exactly how the word gets into the tree.

## MCP (deferred tools & search)
- **A pooled tool is invisible to the model until the reminder advertises it, and a search result is a MENU** (name + how it matched) — the schema reaches the model with the next request. Both are one-write-path invariants: `agent.AddDeferredMCPTools` + `NotifyDeferredToolsAdded()` for the first, the pool for the second.
- **Toggling a server is a GLOBAL fact** (one pool and one connection serve every session): notify all live agents, and unregister from the registry and every session's discovered set — not just from the pool.
- Read `docs/agents/mcp.md` before touching `agent/mcp/`, the search tool, or the reminder.

## Impact Surface
- Five entry modes run the agent loop — `acp`, `tui`, `desktop`, `channel`, `-p` (runAgent); `tachi web` only reads session files. An agent-loop change must account for all five
- They differ in how a Bash policy `ask` is answered (a per-agent `PermissionMode`): `tui` prompts; `acp` and `desktop` delegate through a `PermissionHandler`; `channel`, `-p`, subagents, dream and the one-off commands are `PermissionModeSkip` and APPROVE it — nobody is there to consult, so an `ask` rule only ever prompts where a human is attached and `deny` (decided first) is what still stops a command there. A file tool's `ask` follows the same rule, and its judgment gate is off in that mode. Everything else about permissions — the rule order and the unparseable fallback, the judgment gate that can outrank an ask (never a `deny`), session-scoped approvals, and which trees contribute rules: **`docs/agents/permission.md`**

## Session History & Reminders
- **`ConvertSessionToLLMMessages` must rebuild a history exactly as it was SENT** — the provider caches by prefix, so one extra newline (a reminder seam) misses from there on. The two reminder shapes, and why changing the block's RENDERER is not structural, are in `docs/agents/prompt-cache.md`.
- **A cache hit rate that drops, or a restart that looks expensive**: follow `docs/agents/prompt-cache.md` rather than theorising.

## Session Store (session.FileStore)
- **The session LIST is memoized and `LoadMeta` deliberately is not** (a stale metadata read becomes a lost write), **`meta.json` is written atomically**, and **the desktop builds every manager on ONE store** — the mechanics and the bug each prevents: `docs/agents/session-store.md`.

## @-References (agent/atfile)
- **One scanner owns the syntax, and the FRONTEND expands before the agent is called** (`tui/commands_agent.go`, `desktop/agent_turn.go`) — so a new reference kind is wired in BOTH frontends, and a picker may only offer what `atfile.Expand` reads back (hence `RefForPath`/`RefForSession`: the spelling lives on the expansion side).
- Files are inlined (or annotated, as `[@file: path]`); **`@session:<id>` becomes a POINTER into the session store — id, title, record count and transcript path, never the transcript** (`agent/sessionref`, injected through `atfile.Options.Sessions`). Inlining another conversation would spend this session's context on text nobody asked to read, for the rest of the conversation.

## Skills (agent/skill.Store)
- **A skill directory MAY be a symlink** (the normal way to keep a skill in its own repo and still have it under `~/.tachi/skills`), so the scan must follow one: `os.ReadDir` reports the LINK's type and `filepath.WalkDir` does not open a linked root — `isDirOrDirLink` + the `EvalSymlinks` in `loadSupportingFiles` are what keep such a skill in the reminder, the LLM's list and `/commands`. `Delete` only UNLINKS it; the target tree is not the store's to remove. **The store also reads the agent skills the OS ships** (`$OMARCHY_PATH/default/agents/skills`, scanned LAST so a user copy of a name shadows it, read live instead of symlinked in): `agent/skill/omarchy.go`.

## Checkpoints (agent/checkpoint)
- **A root is identified by its PATH, never by its position, and a turn's binding is SESSION-scoped** — so a moved/edited root set, or auto-compaction swapping the session mid-turn, is where a write silently lands in the wrong tree or gets refused: `docs/agents/checkpoints.md`.

## Test Safety
- Tests write to `t.TempDir()` only; never into `~/.tachi`

## Integration Tests (itest)
- Suites `itest/run|tui|acp|mockllm` (`make itest`; one: `make itest-run|itest-tui|itest-acp|itest-mockllm`).
- **A spec's waits anchor on the AGENT's turn state (`TurnInFlight`), never on the rendered screen**, and the harness caches its binary by git HEAD hash (a dirty tree rebuilds per call — keep it clean). The rest, including mockllm's three wire protocols and the process-global base dirs: `docs/agents/itest.md`.

## Edge Cases
- **One-off paths**: handle the no-session case (fresh TUI, one-off command run directly)

## GitHub Workflows (CI/CD)
- `.github/workflows/`: `ci.yml` (push/PR to `main` → test / build / integration), `release.yml` (tag `v*` → goos/goarch matrix + `action-gh-release`); shared steps under `.github/actions/`
- Build `web/frontend/dist` before any Go compile: it is gitignored but `//go:embed`-ed (`web/frontend/embed.go`) → a fresh checkout fails with `pattern dist: no matching files found`. CI runs `.github/actions/web-build` (node 20 + `npm ci` + `npm run build`) per job
- `go test ./...` compiles `web/frontend`, and `itest/harness.BuildBinary` does a raw `go build .` — both need `dist/` present
- vite 5 needs node `^18.0.0 || >=20.0.0`; CI pins 20; keep `package-lock.json` in sync for `npm ci`

## Desktop Module
- `desktop/` is its own Go module and is NOT listed in the repo-root `go.work`: every Go command for it needs `GOWORK=off` (its own Makefile exports it; the root `desktop-smoke` target sets it)
- The CLI the desktop package ships is the ROOT module's `tachi`, and it is built with `GOWORK=off` too. The local-only channel plugins (`third_party_channels.go`, gitignored) are resolved through `go.work` and therefore do not resolve there: the root Makefile passes `-tags no_workspace` whenever `GOWORK=off`, which is what the file's `//go:build !no_workspace` constraint keys on. Workspace-mode builds still get the plugins — adding a plugin import must not require a go.mod entry
- Wails bindings are generated AND committed: after any change to `AgentService`, run `cd desktop && GOWORK=off wails3 generate bindings -clean=true -ts -i` — never hand-edit, and a frontend call the generator has not seen fails `tsc`
- A desktop change is four surfaces, not one: the Go method, the regenerated TS binding, the frontend, and the smoke driver

## Web Console (Frontend)
- `web/frontend/` = React 18 + Vite 5 + TS + Tailwind; server = `web/server.go` + `web/api.go` (`tachi web`)
- `web/frontend/embed.go` embeds `dist` via `//go:embed dist`, served under a `dist` prefix via `fs.Sub`; dist is gitignored — never commit build output
- `make build` / `build-debug` / `test` / `itest` gate on `web-check`, which runs the npm build only when `dist/index.html` is missing (the check is cheap, the build is not); a bare `go build` has no such gate; CI uses the composite action
