# Tachi - AI Agent CLI

Tachi is a terminal-based AI agent that provides an interactive TUI for LLM conversations with tool use capabilities.

## Build Commands

```bash
# Build the binary
make build

# Build for Linux (cross-compile)
make build-linux

# Run tests
make test

# Run a single test
go test -v ./tools -run TestEditFile

# Build and run directly
go build -o tachi . && ./tachi
```

## Project Architecture

### High-Level Flow

1. **Entry Point (`main.go`)**: Sets up CLI commands, loads config, builds system prompt (embedding `.tachi.md` project context), initializes the agent and TUI
2. **Agent (`agent/agent.go`)**: Core orchestration layer that manages the conversation loop with LLM providers
3. **TUI (`tui/`)**: Bubble Tea-based terminal UI handling user input, streaming output, and tool confirmations
4. **LLM Providers (`llm/`)**: Abstraction over OpenAI and Anthropic APIs with streaming support
5. **Tools (`tools/`)**: File operations (Read, Write, Edit, Glob, Grep), Bash execution, WebSearch, AskUser
6. **Session (`session/`)**: Conversation persistence using JSONL messages + JSON metadata per session
7. **Config (`config/`)**: YAML config loading, resolution of providers/models, CLI flag merging

### Storage Locations (all under `~/.tachi/`)

| Path | Purpose |
|------|---------|
| `config.yaml` | Provider configurations |
| `input_history` | Persistent TUI input history |
| `session/` | Session directories (JSONL messages + JSON metadata) |
| `logs/debug.log` | Debug log (used via `debuglog.Log()`) |

### Key Components

**Agent Loop (`agent/agent.go`)**:
- `RunConversationStream()` runs the main event loop, streaming `AgentEvent`s to the TUI
- Handles tool calls with confirmation flow for destructive operations (EditFile), plus AskUser for interactive questions
- Supports iteration budget to prevent infinite loops
- Accumulates message history for multi-turn conversations
- Handles `max_tokens`/`length` finish reason by auto-continuing (up to 3 retries)

**TUI State Machine (`tui/model.go`)**:
- `stateIdle` → `stateWaiting` (after user submits) → `stateStreaming` (receiving LLM output)
- `stateAwaitingConfirmation`: Pauses for user approval on file edits (shows diff)
- `stateAskUserQuestion`: Interactive form when LLM uses AskUser tool
- `stateSelectingModel`: Provider switcher via `/model` command
- `Ctrl+S` toggles copy mode for selecting text with the mouse (disables mouse scroll)

**Tool System (`tools/tool.go`)**:
- Tools implement `Tool` interface with JSON schema for LLM
- `ConfirmationTool` interface for tools requiring user approval (EditFile)
- `AskUserQuestionError` pattern: special error type that signals the agent to pause for user interaction
- `Registry` pattern for tool discovery and invocation with three-phase execution: Invoke → Confirm → ExecuteConfirmed
- EditFile tool includes smart curly-quote normalization for matching

**Config (`config/config.go`)**:
- YAML config at `~/.tachi/config.yaml`
- Supports multiple named providers with type, model, API key, base URL, and optional context window override
- API keys resolved via env vars (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`) or config file
- CLI flags override config values (`--provider`, `--model`, `--max-tokens`, `--max-iterations`, `--resume`)
- Web search config supports Brave, Serper, and SerpAPI providers

### Session Management

Sessions persist conversations to disk under `~/.tachi/session/<session-id>/`:
- `meta.json`: Session metadata (id, title, provider, model, timestamps)
- `messages.jsonl`: Append-only JSON Lines file of all messages (user, assistant, thinking, tool_call, tool_result)

Key behaviors:
- A session is auto-created on first user message
- `/clear` ends the current session (new one created on next message)
- `--resume`/`-r` flag reloads the most recent session and continues from where it left off
- `agent/session_convert.go` converts flat session messages back into provider-specific `llm.Message` format

### Provider-Specific Thinking Handling

Anthropic natively supports thinking blocks. OpenAI does not. When converting session messages back to LLM format (for `--resume`):
- **Anthropic**: Thinking blocks are attached as `ThinkingBlocks` on the assistant message
- **OpenAI**: Thinking content is prepended into the assistant's `Content` string so context is preserved

### Slash Commands

- `/clear` - Clear conversation history and end current session
- `/model` - Switch between configured providers interactively
- `/commit` - Auto-generate commit message via LLM and git commit
- `/init` - Generate `.tachi.md` project context file
- `/quit` - Exit

### Context Window Tracking

The status bar shows input token usage as a fraction of the model's context window with color-coded percentage:
- Normal (<50%), Warning (50-80%), High (>80%)
- Context window resolved from: config override → `llm/model_info.go` lookup → 128K default

### Input History

Persistent input history stored in `~/.tachi/input_history`. Navigate with `Ctrl+P` (prev) / `Ctrl+N` (next). Configurable via `tui.input_history_limit` (0 disables, default 10).

### Streaming Architecture

The LLM provider interface uses channels for streaming:
- `StreamEvent` types: `text_delta`, `thinking_delta`, `tool_use_start`, `input_json_delta`, `signature_delta`
- Agent consumes stream and forwards events to TUI via `agentEventMsg`
- TUI renders deltas incrementally in the chat view with glamour markdown rendering

## CLI

```bash
# Interactive TUI (default)
tachi

# Resume most recent session
tachi --resume

# Non-interactive single-turn (with streaming output)
tachi run --prompt "Explain this codebase"

# Initialize config file
tachi init
```

## Testing

Tests are co-located with source files. Run individual test files:
