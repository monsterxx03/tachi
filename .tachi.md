# Tachi - AI Agent CLI

Tachi is a terminal-based AI agent that provides an interactive TUI for LLM conversations with tool use capabilities.

## Build Commands

```bash
# Build the binary
make build

# Run tests
make test

# Run a single test
go test -v ./tools -run TestEditFile

# Build and run directly
go build -o tachi . && ./tachi
```

## Project Architecture

### High-Level Flow

1. **Entry Point (`main.go`)**: Sets up CLI commands, loads config, initializes the agent and TUI
2. **Agent (`agent/agent.go`)**: Core orchestration layer that manages the conversation loop with LLM providers
3. **TUI (`tui/`)**: Bubble Tea-based terminal UI handling user input, streaming output, and tool confirmations
4. **LLM Providers (`llm/`)**: Abstraction over OpenAI and Anthropic APIs with streaming support
5. **Tools (`tools/`)**: File operations (Read, Write, Edit, Glob, Grep), Bash execution, WebSearch, AskUser

### Key Components

**Agent Loop (`agent/agent.go`)**:
- `RunConversationStream()` runs the main event loop, streaming `AgentEvent`s to the TUI
- Handles tool calls with confirmation flow for destructive operations (EditFile)
- Supports iteration budget to prevent infinite loops
- Accumulates message history for multi-turn conversations

**TUI State Machine (`tui/model.go`)**:
- `stateIdle` → `stateWaiting` (after user submits) → `stateStreaming` (receiving LLM output)
- `stateAwaitingConfirmation`: Pauses for user approval on file edits (shows diff)
- `stateAskUserQuestion`: Interactive form when LLM uses AskUser tool
- `stateSelectingModel`: Provider switcher via `/model` command

**Tool System (`tools/tool.go`)**:
- Tools implement `Tool` interface with JSON schema for LLM
- `ConfirmationTool` interface for tools requiring user approval (EditFile)
- `Registry` pattern for tool discovery and invocation
- EditFile tool includes smart curly-quote normalization for matching

**Config (`config/config.go`)**:
- YAML config at `~/.tachi/config.yaml`
- Supports multiple providers with named configurations
- CLI flags override config values (`--provider`, `--model`, `--max-tokens`)

### Slash Commands

The TUI supports these commands (defined in `tui/commands.go`):
- `/clear` - Clear conversation history
- `/model` - Switch between configured providers
- `/commit` - Auto-generate commit message via LLM and git commit
- `/init` - Generate `.tachi.md` project context file
- `/quit` - Exit

### Input History

Persistent input history stored in `~/.tachi/input_history`. Navigate with `Ctrl+P` (prev) / `Ctrl+N` (next). Configurable via `tui.input_history_limit` in config (0 disables, default 10).

### Streaming Architecture

The LLM provider interface uses channels for streaming:
- `StreamEvent` types: `text_delta`, `thinking_delta`, `tool_use_start`, `input_json_delta`
- Agent consumes stream and forwards events to TUI via `agentEventMsg`
- TUI renders deltas incrementally in the chat view

## Testing

Tests are co-located with source files. Run individual test files:
```bash
go test -v ./tools -run TestGlob
go test -v ./config -run TestResolve
```

## Key Dependencies

- `charm.land/bubbletea/v2` - TUI framework
- `charm.land/bubbles/v2` - Text input, spinner components
- `charm.land/lipgloss/v2` - Styling
- `github.com/anthropics/anthropic-sdk-go` - Anthropic API
- `github.com/sashabaranov/go-openai` - OpenAI API
- `github.com/urfave/cli/v3` - CLI framework
