# Tachi — Development Conventions (Agent Guide)

## Code Organization
- Reuse `pkg/` before writing anything new (`logger`, `strutil`, `httpx`, `fileutil`, `container`, `shutil`, …); never re-implement existing capability
- Business-agnostic logic goes into the matching `pkg/`, not inline in business code

## Context Passing
- Pass `context.Context` only when it is used (logging, cancellation, ctx values). No decorative params.

## Quality Assurance
- `make lint` must pass before ending a turn; disable a rule explicitly when it is meaningless for the code
- No magic values: named constants, defined once
- Readability first: refactor instead of piling on; ask before large changes

## Impact Surface
- Four agent entry modes: `acp`, `tui`, `channel`, `-p` (runAgent). Agent-loop changes must account for all four

## Test Safety
- Tests write to `t.TempDir()` only; never into `~/.tachi`

## Integration Tests (itest)
- Suites: `itest/run`, `itest/tui`, `itest/acp`, `itest/mockllm` (run/tui/acp depend on mockllm)
- `make itest` (= `make -j4` + `ginkgo -p`); one suite: `make itest-run|itest-tui|itest-acp|itest-mockllm`
- `itest/tui` drives the real `tui.Model` + `AIAgent` in-process under `tea.NewProgram` (keys via `p.Send(tea.KeyPressMsg)`); ANSI diff stream is replayed through `itest/tui/vt.go`, so `Screen()` == a real terminal
- `config.SetBaseDir` / `tools.SetWorkingDir` are process globals — safe only because ginkgo parallel nodes are separate processes with serial specs; pin a fresh working dir per spec (a deleted `t.TempDir` makes Bash fork/exec fail)
- `itest/harness.BuildBinary` caches the binary by git HEAD hash in `os.TempDir()/tachi-itest-<hash>`; a dirty tree falls back to per-call builds → keep the tree clean
- mockllm speaks 3 wire protocols (openai / anthropic / openai-res); a new one needs route + normalize + render + contract tests
- Hermetic: the harness config disables `herdr`; never touch the real `~/.tachi`

## Desktop Smoke Verification (demo + mockllm)

Verifies desktop-only paths (Wails wiring, rendered UI, end-to-end flows); unit tests and itest cannot see whether a binding's result reaches a card.

### Recipe — launch → drive → capture → kill in ONE shell invocation

```bash
# one-time: copy the bundle, rename Contents/MacOS/Tachi → TachiSmoke,
#           rewrite CFBundleExecutable/Name/Identifier, re-sign
cp -R desktop/bin/Tachi.app /tmp/tachi-smoke/TachiSmoke.app
codesign --force --deep --sign - /tmp/tachi-smoke/TachiSmoke.app

# every run
cd desktop && make frontend                     # frontend/dist is //go:embed-ed
GOWORK=off go build -o bin/Tachi .              # bare binary is all the bundle needs
cp bin/Tachi /tmp/tachi-smoke/TachiSmoke.app/Contents/MacOS/TachiSmoke
codesign --force --deep --sign - /tmp/tachi-smoke/TachiSmoke.app

pkill -f TachiSmoke; sleep 2; test "$(pgrep -f TachiSmoke | wc -l)" = 0
HOME=/tmp/tachi-smoke /tmp/mockllm-bin &        # writes config.yaml + dumps requests
MOCK=$!; sleep 2
open /tmp/tachi-smoke/TachiSmoke.app \
  --env HOME=/tmp/tachi-smoke --env TACHI_DEMO=1 --env TACHI_DEMO_JS=/tmp/drive.js
sleep 6                                         # mount; the demo JS starts 2s after mount
sleep 18                                        # let the driver run its steps
R=$(osascript -e 'tell application "System Events" to tell process "TachiSmoke" to get {position, size} of window 1')
IFS=', ' read X Y W H < <(echo "$R" | tr -dc '0-9, ')   # "{360, 166, 1199, 779}" → logical points
screencapture -x -R "$X,$Y,$W,$H" /tmp/tachi-smoke/shot.png
pkill -f TachiSmoke; kill $MOCK
```

- `--env TACHI_DESKTOP_APPEARANCE=dark|light` forces a theme (dev aid); run twice for both palettes

### Driver JS (`TACHI_DEMO_JS`, injected once by `desktop/demo.go` ~2s after mount)

```js
// React inputs ignore `el.value = …`: native setter + input event
const type = (el, t) => {
  Object.getOwnPropertyDescriptor(HTMLTextAreaElement.prototype, 'value').set.call(el, t)
  el.dispatchEvent(new Event('input', { bubbles: true }))
}
// window-capture key handlers (e.g. ViewerOverlay Esc): dispatch on the focused element
const esc = () => (document.activeElement || window)
  .dispatchEvent(new KeyboardEvent('keydown', { key: 'Escape', bubbles: true, cancelable: true }))
// per-step assertions → #smoke-result (position:fixed; bottom:0; monospace)
window.addEventListener('error', (e) => banner('JS ERROR: ' + e.message))
```

- Assertions in the banner, not the console: one screenshot carries UI + pass/fail; a Go↔TS field mismatch shows as a red bar, not silence
- App restores the newest session itself; if it lands elsewhere, click the matching `.session` row
- `scrollIntoView` before clicking anything off-screen; `onMouseDown` components (pickers) need `dispatchEvent(new MouseEvent('mousedown'))`

### Rules & traps

- Isolated `HOME`: sessions, config, `desktop_ui.json`, logs land in the throwaway dir; needs a `config.yaml` with a provider, else `prepareSession` fails → empty transcript, no error
- Bundle: `open -a <path>` matches by BUNDLE, `pkill -f "Tachi.app/Contents/MacOS/Tachi"` by EXECUTABLE PATH — both hit the user's running app. `TachiSmoke` is safe on both
- Launch via `open --env`, never the executable: only LaunchServices makes the window frontmost. Traps: a live previous instance is merely activated and receives NO env (hence the `pgrep` assert); a direct exec + an `open` copy coexist and share one HOME → duplicate turns in the transcript
- Fixtures: `$HOME/.tachi/session/<id>/{meta.json,messages.jsonl}`, shapes as `session.Store` (`type: user/assistant/tool_call/tool_result`, `tool_call_id` pairing, `args` as a JSON OBJECT); bump `updated_at` so the app auto-loads it. Add what the feature needs: a `git init` repo with a dirty tree, `additional_dirs`, `desktop_ui.json`
- Scripted LLM: mockllm is an in-process lib (no binary) → write a driver: `mockllm.NewServer(mockllm.WithProtocol(mockllm.ProtocolOpenAI))`, `Script(Step{Reply: Stream(ToolCallStart(id, tool, argsJSON), Finish("tool_calls"), Usage(…), Done())})`, print `BaseURL()`, block. One protocol per driver. Keep `title_generation: false` in the config or an unscripted request eats a step
- The mock writes `config.yaml` itself (random port — hand-editing cannot work) and dumps `mock.Requests()` messages to a file: verify the prompt at the LLM boundary, not just the rendered bubble
- Driver source can live outside the repo: `go build -o /tmp/mockllm-bin /tmp/smoke/main.go` from the repo root resolves `itest/mockllm` via the repo module (no go.mod, no network)
- Mock + app + capture + kill in ONE invocation: a background process started by a finished tool call gets reaped → app fails with `connection refused`
- Capture: `screencapture -x -R x,y,w,h` (logical points); `-l <windowid>` is blank for an occluded window (WebKit does not composite what nobody sees) → front it first. Confirm the shot is your instance (titlebar / session id)
- Not proven here: provider behaviour, model quality, human feel/perf. Native dialogs (folder pickers) cannot be driven this way — cover with Go tests

## Edge Cases
- **One-off paths**: handle the no-session case (fresh TUI, one-off command run directly)

## GitHub Workflows (CI/CD)
- `.github/workflows/`: `ci.yml` (push/PR to `main` → test / build / integration), `release.yml` (tag `v*` → goos/goarch matrix + `action-gh-release`); shared steps under `.github/actions/`
- Build `web/frontend/dist` before any Go compile: it is gitignored but `//go:embed`-ed (`web/frontend/embed.go`) → a fresh checkout fails with `pattern dist: no matching files found`. CI runs `.github/actions/web-build` (node 20 + `npm ci` + `npm run build`) per job
- `go test ./...` compiles `web/frontend`, and `itest/harness.BuildBinary` does a raw `go build .` — both need `dist/` present
- vite 5 needs node `^18.0.0 || >=20.0.0`; CI pins 20; keep `package-lock.json` in sync for `npm ci`

## Web Console (Frontend)
- `web/frontend/` = React 18 + Vite 5 + TS + Tailwind; server = `web/server.go` + `web/api.go` (`tachi web`)
- `web/frontend/embed.go` embeds `dist` via `//go:embed dist`, served under a `dist` prefix via `fs.Sub`; dist is gitignored — never commit build output
- `make build` always runs `web-build`; `make web-check` builds only when `dist/index.html` is missing (cheap for `make test` / `make itest`); CI uses the composite action
