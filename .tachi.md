# Tachi — Development Conventions (Agent Guide)

## Code Organization

- **Prefer reusing shared packages under `pkg/`** (`logger`, `strutil`, `httpx`, `fileutil`, `container`, `shutil`, etc.); never re-implement an existing capability
- Extract **business-agnostic** common logic into the corresponding package under `pkg/`, instead of scattering it across business code

## Context Passing

- Pass `context.Context` between functions **as needed**: when logging, propagating cancellation, or reading ctx values — pass it; when it is not used, do not force it, to avoid polluting signatures with meaningless context parameters

## Quality Assurance

- Run **`make lint` before the end of every turn** and ensure it passes; if a lint rule is meaningless for the current code, explicitly disable that rule
- **Predefine constants**: do not hard-code magic values in code logic; keep constants defined in one place
- **Readability first**: if adding logic degrades readability of existing code, prefer refactoring; for large changes, get user consent first

## Impact Surface

- **There are four agent entry modes**: `acp`, `tui`, `channel`, `-p` (runAgent). When changing core agent-loop logic, consider the impact on every entry mode

## Test Safety

- When unit tests need to write local files, **always use `t.TempDir()`**; never write into the user's `~/.tachi` directory

## Integration Tests (itest)

- **Suites under `itest/`**: `itest/run` (run command), `itest/tui` (in-process TUI), `itest/acp` (ACP protocol), `itest/mockllm` (mock LLM server); the run/tui/acp suites depend on mockllm
- **Run via `make itest`** (internally `make -j4` + `ginkgo -p` in parallel); individual suites via `make itest-run` / `itest-tui` / `itest-acp` / `itest-mockllm`
- **`itest/tui` drives the real TUI in-process** (no tmux, no binary build): a real `tui.Model` + real `AIAgent` inside `tea.NewProgram` with injected input/output; keys via `p.Send(tea.KeyPressMsg)`. The renderer's ANSI diff stream is replayed through a self-built virtual terminal (`itest/tui/vt.go`) so `Screen()` returns what a real terminal shows
- **Process-global state in itest/tui**: `config.SetBaseDir` and `tools.SetWorkingDir` are process globals — safe only because ginkgo parallel nodes are separate processes with serial specs; the driver pins a fresh working dir per spec (a stale deleted `t.TempDir` makes Bash fork/exec fail)
- **Shared harness in `itest/harness/`**: `BuildBinary` caches the compiled binary keyed by git HEAD hash under `os.TempDir()/tachi-itest-<hash>`; a dirty workspace falls back to per-call builds, so keep the tree clean before committing
- **mockllm covers three wire protocols** (openai / anthropic / openai-res); a new protocol needs server route + normalize + render + contract tests
- **Tests must stay hermetic**: the harness configYAML template disables `herdr`; never touch the real `~/.tachi`

## Edge Cases

- When modifying **one-off paths**, account for the **no-session** case (e.g. TUI just started, running a one-off command directly)

## GitHub Workflows (CI/CD)

- **Workflows under `.github/workflows/`**: `ci.yml` (push/PR to `main` → `test` / `build` / `integration` jobs), `release.yml` (tag `v*` → goos/goarch matrix build + `action-gh-release`); shared steps live in composite actions under `.github/actions/`
- **Frontend must be built before any Go compile**: `web/frontend/dist` is gitignored yet embedded via `web/frontend/embed.go` (`//go:embed dist`), so a fresh checkout fails every Go compile (`pattern dist: no matching files found`). CI runs `.github/actions/web-build` (setup-node 20 + `npm ci` + `npm run build`) in each job before touching Go
- **Watch out when editing workflows**: `go test ./...` compiles the `web/frontend` package, and the itest harness (`itest/harness.BuildBinary`) does a raw `go build .` — both need `dist/` present
- **Node toolchain**: vite 5 requires Node `^18.0.0 || >=20.0.0`; CI pins Node 20, and `npm ci` requires `package-lock.json` to stay in sync (don't leave an out-of-sync lockfile)

## Web Console (Frontend)

- **Frontend lives in `web/frontend/`** (React 18 + Vite 5 + TypeScript + Tailwind); the HTTP server is `web/server.go` + `web/api.go` (`tachi web` command)
- **`web/frontend/embed.go` embeds `web/frontend/dist`** into the Go binary via `//go:embed dist` (served under a `dist` prefix via `fs.Sub`); the dist tree is gitignored — never commit build output
- **Build flows**: `make build` always runs `web-build` (`npm install && npm run build`); `make web-check` builds only when `dist/index.html` is missing (cheap for local `make test` / `make itest` on a fresh checkout); CI uses the composite action instead
