# Tachi — Development Conventions (Agent Guide)

## Splits — read on demand

The conventions that hold anywhere in the repo are here; anything area-specific lives in a handbook
beside this file and is read only when it matters — a new lesson goes into the handbook it belongs to,
not here.

- **`docs/agents/desktop.md`** — read it **before changing anything under `desktop/`**: the smoke
  suite (drivers, fixtures, bundle/pkill/suspension rules, and the traps that make a green run mean
  nothing), macOS build & signing (ad-hoc vs `make sign-local`, TCC), the Wails-backend conventions
  (generated bindings, session paths, open/reveal), and the frontend's UI-state conventions (which
  module owns the transcript, the sidebar, the events, the composer, the panel width). Its top table
  says which section to read when — read that section, not necessarily the whole file.

## Code Organization
- Reuse `pkg/` before writing anything new (`logger`, `strutil`, `httpx`, `fileutil`, `container`, `shutil`, …); never re-implement existing capability
- Business-agnostic logic goes into the matching `pkg/`, not inline in business code

## Context Passing
- Pass `context.Context` only when it is used (logging, cancellation, ctx values). No decorative params.

## Quality Assurance
- `make lint` must pass before ending a turn; disable a rule explicitly when it is meaningless for the code
- No magic values: named constants, defined once
- Readability first: refactor instead of piling on; ask before large changes

## Commits

- **Never commit unless the user asks.** Finish the work, run the checks (`make lint`, tests), then report — list the changed files and, if useful, a suggested commit message, but leave git untouched. Commit timing and granularity are the user's call.
- **Never `git add -A`/`git add .`**: a neighbouring session may have unrelated work in the tree (this has already happened once — another session's icon files were swept into an unrelated commit). Stage the files you changed, by name.

## Impact Surface
- Five entry modes run the agent loop — `acp`, `tui`, `desktop`, `channel`, `-p` (runAgent); `tachi web` only reads session files. An agent-loop change must account for all five
- They differ in how a Bash policy `ask` is answered (a per-agent `PermissionMode`): `tui` prompts, `acp` and `desktop` delegate through a `PermissionHandler`; `channel`, `-p`, subagents, dream and the one-off commands are `PermissionModeSkip` and REFUSE the command — a command the policy cannot parse (unterminated quoting or a here-doc left open; NOT heredocs as such, those parse and are judged by the commands they run) is conservatively an `ask`, so there it is refused outright: fix the syntax. A session-wide allow (the TUI's `a`, the desktop card's middle button) stops the asking for that conversation only, and never overrides a `deny` — deny is decided before an ask is raised. It does not cover the unparseable fallback either: that verdict is reached before any rule is consulted, so a command the parser cannot read is confirmed every time

## Session History & Reminders
- **`ConvertSessionToLLMMessages` must rebuild a history exactly as it was SENT.** The provider caches prompts by PREFIX (server-side, not the client's `cache_control` markers), so one extra newline or a block in the wrong position makes every turn appended since the last reload miss the cache and re-read the whole tail — measured at ~47k tokens from a single stray `\n` at a reminder seam, and ~290k when the tool list changed. Two shapes share `MessageTypeReminder`, told apart only by position: a wrapper for the NEXT user message (its next non-reminder record IS a user message — artifacts, the date block, continuation prompts) and a block the loop injected mid-turn, which is its own message and must stay where it was sent.
- Detail + evidence: [plan-panel design §7](docs/2026-09-12-desktop-plan-panel-design.md).

## Test Safety
- Tests write to `t.TempDir()` only; never into `~/.tachi`

## Integration Tests (itest)
- Suites: `itest/run`, `itest/tui`, `itest/acp`, `itest/mockllm` (run/tui/acp depend on mockllm)
- `make itest` (= `make -j4` + `ginkgo -p`); one suite: `make itest-run|itest-tui|itest-acp|itest-mockllm`
- `itest/tui` drives the real `tui.Model` + `AIAgent` in-process under `tea.NewProgram` (keys via `p.Send(tea.KeyPressMsg)`); ANSI diff stream is replayed through `itest/tui/vt.go`, so `Screen()` == a real terminal
- `config.SetBaseDir` / `tools.SetWorkingDir` are process globals — safe only because ginkgo parallel nodes are separate processes with serial specs; pin a fresh working dir per spec (a deleted `t.TempDir` makes Bash fork/exec fail)
- `itest/harness.BuildBinary` caches the binary by git HEAD hash in `os.TempDir()/tachi-itest-<hash>`; a dirty tree falls back to per-call builds → keep the tree clean
- mockllm speaks 3 wire protocols (openai / anthropic / openai-res); a new one needs route + normalize + render + contract tests
- Hermetic: the harness config disables `herdr`; never touch the real `~/.tachi`

## Edge Cases
- **One-off paths**: handle the no-session case (fresh TUI, one-off command run directly)

## GitHub Workflows (CI/CD)
- `.github/workflows/`: `ci.yml` (push/PR to `main` → test / build / integration), `release.yml` (tag `v*` → goos/goarch matrix + `action-gh-release`); shared steps under `.github/actions/`
- Build `web/frontend/dist` before any Go compile: it is gitignored but `//go:embed`-ed (`web/frontend/embed.go`) → a fresh checkout fails with `pattern dist: no matching files found`. CI runs `.github/actions/web-build` (node 20 + `npm ci` + `npm run build`) per job
- `go test ./...` compiles `web/frontend`, and `itest/harness.BuildBinary` does a raw `go build .` — both need `dist/` present
- vite 5 needs node `^18.0.0 || >=20.0.0`; CI pins 20; keep `package-lock.json` in sync for `npm ci`

## Desktop Module
- `desktop/` is its own Go module and is NOT listed in the repo-root `go.work`: every Go command for it needs `GOWORK=off` (its own Makefile exports it; the root `desktop-smoke` target sets it)
- Wails bindings are generated AND committed: after any change to `AgentService`, run `cd desktop && GOWORK=off wails3 generate bindings -clean=true -ts -i` — never hand-edit, and a frontend call the generator has not seen fails `tsc`
- A desktop change is four surfaces, not one: the Go method, the regenerated TS binding, the frontend, and the smoke driver

## Web Console (Frontend)
- `web/frontend/` = React 18 + Vite 5 + TS + Tailwind; server = `web/server.go` + `web/api.go` (`tachi web`)
- `web/frontend/embed.go` embeds `dist` via `//go:embed dist`, served under a `dist` prefix via `fs.Sub`; dist is gitignored — never commit build output
- `make build` always runs `web-build`; `make web-check` builds only when `dist/index.html` is missing (cheap for `make test` / `make itest`); CI uses the composite action
