# Tachi - AI Agent CLI

Tachi is a terminal-based AI agent that provides an interactive TUI for LLM conversations with tool use capabilities.

## Build Commands

```bash
# Build the binary
make build

# Build for Linux (cross-compile)
make build-linux

# Run all tests
make test

# Run a single test
go test -v ./tools -run TestEditFile

# Build and run directly
go build -o tachi . && ./tachi
```

## Project Architecture

### High-Level Flow

1. **Entry Point (`main.go`)**: Sets up CLI commands, loads config, builds system prompt (embedding `.tachi.md` project context), initializes the agent and TUI
2. **Agent (`agent/agent.go`)**: Core orchestration layer that manages the conversation loop with LLM providers
3. **TUI (`tui/`)**: Bubble Tea-based terminal UI handling user input, streaming output, and tool confirmations
4. **LLM Providers (`llm/`)**: Abstraction over OpenAI and Anthropic APIs with streaming support
5. **Tools (`agent/tools/`)**: File operations (Read, Write, Edit, Glob, Grep), Bash execution, WebSearch, AskUser
6. **Session (`session/`)**: Conversation persistence using JSONL messages + JSON metadata per session
7. **Config (`config/`)**: YAML config loading, resolution of providers/models, CLI flag merging

### Storage Locations (all under `~/.tachi/`)

| Path | Purpose |
|------|---------|
| `config.yaml` | Provider configurations |
| `input_history` | Persistent TUI input history |
| `session/` | Session directories (JSONL messages + JSON metadata) |
| `mcp_tokens/` | OAuth token files for MCP servers (one JSON per server) |
| `logs/debug.log` | Debug log (used via `debuglog.Log()`) |

### Key Components

**Agent Loop (`agent/agent.go`)**:
- `RunConversationStream()` runs the main event loop, streaming `AgentEvent`s to the TUI
- Handles tool calls with confirmation flow for destructive operations (EditFile), plus AskUser for interactive questions
- Supports iteration budget to prevent infinite loops
- Accumulates message history for multi-turn conversations
- Handles `max_tokens`/`length` finish reason by auto-continuing (up to 3 retries)

**TUI State Machine (`tui/model.go`)**:
- `stateIdle` → `stateWaiting` (after user submits) → `stateStreaming` (receiving LLM output)
- `stateAwaitingConfirmation`: Pauses for user approval on file edits (shows diff)
- `stateAskUserQuestion`: Interactive form when LLM uses AskUser tool
- `stateSelectingModel`: Provider switcher via `/model` command
- `stateSelectingSession`: Session browser via `/sessions` command
- `Ctrl+O` toggles a fullscreen thinking-only view during streaming
- `Ctrl+S` toggles copy mode for selecting text with the mouse (disables mouse scroll)

**Tool System (`agent/tools/tool.go`)**:
- Tools implement `Tool` interface with JSON schema for LLM
- `ConfirmationTool` interface for tools requiring user approval (EditFile)
- `AskUserQuestionError` pattern: special error type that signals the agent to pause for user interaction
- `Registry` pattern for tool discovery and invocation with three-phase execution: Invoke → Confirm → ExecuteConfirmed
- EditFile tool includes smart curly-quote normalization for matching

### System Reminder Injection (`agent/systemreminder/`)

Dynamic `<system-reminder>` blocks are injected at the top of user messages (not in the static system prompt) to keep the model aware of transient context without bloating the system prompt. Reminders include:

- **DateReminder**: Current date on first message
- **ProjectContextReminder**: Contents of `.tachi.md` on first message
- **GitReminder**: Branch + porcelain status on first message (configurable via `system_reminder.git_reminder`)
- **IterationWarningReminder**: Warns when remaining iterations are low (threshold configurable)
- **TokenWarningReminder**: Warns when context window usage exceeds a percentage threshold

These are aggregated by `Collector.Collect()` and wrapped in `<system-reminder>...</system-reminder>` tags. Default reminders are set in `AIAgent.NewAIAgent()` and can be replaced with `SetReminderCollector()`.

### MCP (Model Context Protocol) Integration (`agent/mcp/`)

Connects to external tool servers via the MCP protocol. Managed by `mcp.Manager` which handles:

- **Transport**: stdio (subprocess) or HTTP (Streamable HTTP)
- **OAuth2**: HTTP servers can use OAuth2 with browser-based callback (local HTTP server on port 18273–18283) or manual copy-paste flow. PKCE always enabled. Tokens persisted to `~/.tachi/mcp_tokens/<name>.json` via `FileTokenStore`. Dynamic client registration (DCR) runs automatically when `client_id` is not configured; DCR credentials are saved to `<name>_dcr.json` and reloaded across restarts for token refresh.
- **DCR discovery**: After probing the server URL for a 401 with `resource_metadata` in `WWW-Authenticate`, the registration endpoint is discovered via the MCP spec chain — PRM → `authorization_servers` → AS metadata (`/.well-known/oauth-authorization-server`) → `registration_endpoint`. The PRM/AS discovery itself is delegated to mcp-go; tachi only feeds it the correct `ProtectedResourceMetadataURL`.
- **Tool discovery**: `ListTools` after `Initialize` handshake. If `ListTools` fails with `ErrOAuthAuthorizationRequired`, the manager returns an `OAuthRequiredError` prompting the user to run `/mcp auth <name>`.
- **Tool execution**: Wrapped as `MCPTool` implementing the `tools.Tool` interface, named `mcp__<server>__<tool>`

Config in `~/.tachi/config.yaml` under `mcp_servers`. Each HTTP server can have an `oauth:` block with `client_id` (optional — DCR runs if absent), `client_secret`, `scopes`, `client_uri`, and `auth_server_metadata_url`. The TUI exposes management via `/mcp list`, `/mcp toggle <name>`, `/mcp reconnect <name>`, and `/mcp auth <name> [redirect-url]`. MCP tools are auto-registered on agent startup and can be dynamically added/removed at runtime.

### Channel / IM Integration (`channel/`)

`channel.Manager` bridges IM platforms (WeChat, Slack, Telegram) to the AI agent:

- Each IM `ThreadID` maps to a persistent session (like TUI sessions), giving conversations memory
- Agent runs with `skip_edit_confirm=true` (auto-approved edits) and `AskUserQuestion` unregistered
- `drainEvents()` consumes agent events and returns the final assistant text as a reply
- Channels implement the `Channel` interface: `Run(ctx, handler)` — long-polling or webhook models both fit
- Multiple channels can run concurrently; each incoming message creates a fresh agent instance
- **Slash commands**: `/new` starts a fresh session (ends current), `/mcp` lists configured MCP servers. Other slash commands return a help message.

### @-File References (`tui/at_file.go`)

Typing `@` in the input triggers fuzzy file completion using a cached `PathTrie` (built from `rg --files`, cached 30s). On submit, `ExpandAtReferences()` injects the contents of referenced files or directory listings into the message sent to the LLM, while the TUI display keeps the unexpanded `@path` markers. Binary files and files >256KB are rejected.

### Input Features (`tui/input.go`)

- **Paste threshold**: Pastes exceeding 5 lines are collapsed into a placeholder (`[Pasted N lines]`), with full text stored in `pasteBuffer` and sent to the LLM on submit
- **Slash-command completion**: Tab to complete, ↑↓ to navigate
- **History navigation**: `Ctrl+P`/`Ctrl+N` to browse persistent input history (`~/.tachi/input_history`)

### Config (`config/config.go`)

- YAML config at `~/.tachi/config.yaml`
- Supports multiple named providers with type, model, API key, base URL, and optional context window override
- API keys resolved via env vars (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`) or config file
- CLI flags override config values (`--provider`, `--model`, `--max-tokens`, `--max-iterations`, `--resume`)
- Web search config supports Brave, Serper, and SerpAPI providers
- `language` field sets LLM reply language (defaults to English)
- `max_iterations`: nil = default (50), 0 = unlimited, >0 = explicit limit. Only enforced for `tachi run` (single-shot); TUI and channel modes always run unlimited.
- `system_reminder` section: configurable thresholds for iteration/token warnings, git reminder toggle

### Session Management

Sessions persist conversations to disk under `~/.tachi/session/<session-id>/`:
- `meta.json`: Session metadata (id, title, provider, model, timestamps, optional ThreadID for channel sessions)
- `messages.jsonl`: Append-only JSON Lines file of all messages (user, assistant, thinking, tool_call, tool_result)

Key behaviors:
- A session is auto-created on first user message
- `/new` ends the current session (new one created on next message)
- `--resume`/`-r` flag reloads the most recent session and continues from where it left off
- `/sessions` opens an interactive session browser to switch between past sessions
- `agent/session_convert.go` converts flat session messages back into provider-specific `llm.Message` format
- `Manager.FindByThreadID()` enables channel sessions to resume by ThreadID instead of session ID

### Provider-Specific Thinking Handling

Anthropic natively supports thinking blocks. OpenAI does not. When converting session messages back to LLM format (for `--resume`):
- **Anthropic**: Thinking blocks are attached as `ThinkingBlocks` on the assistant message
- **OpenAI**: Thinking content is prepended into the assistant's `Content` string so context is preserved

### Slash Commands

- `/new` - Start new conversation (end current session)
- `/model` - Switch between configured providers interactively
- `/commit` - Auto-generate commit message via LLM and git commit (includes Co-authored-by trailer)
- `/init` - Generate `.tachi.md` project context file
- `/mcp list|toggle <name>|reconnect <name>|auth <name> [redirect-url]` - MCP server management & OAuth authorization
- `/sessions` - Browse and reload previous sessions
- `/quit` - Exit

### Context Window Tracking

The status bar shows input token usage as a fraction of the model's context window with color-coded percentage:
- Normal (<50%), Warning (50-80%), High (>80%)
- Context window resolved from: config override → `llm/model_info.go` lookup → 128K default

### Streaming Architecture

The LLM provider interface uses channels for streaming:
- `StreamEvent` types: `text_delta`, `thinking_delta`, `tool_use_start`, `input_json_delta`, `signature_delta`
- Agent consumes stream and forwards events to TUI via `agentEventMsg`
- TUI renders deltas incrementally in the chat view with glamour markdown rendering

## CLI

```bash
# Interactive TUI (default)
tachi

# Resume most recent session
tachi --resume

# Non-interactive single-turn (with streaming output)
tachi run --prompt "Explain this codebase"

# Initialize config file
tachi init
```
