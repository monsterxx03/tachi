# Tachi — Development Conventions (Agent Guide)

## Code Organization

- **Prefer reusing shared packages under `pkg/`** (`logger`, `strutil`, `httpx`, `fileutil`, `container`, `shutil`, etc.); never re-implement an existing capability
- Extract **business-agnostic** common logic into the corresponding package under `pkg/`, instead of scattering it across business code

## Context Passing

- Pass `context.Context` between functions **as needed**: when logging, propagating cancellation, or reading ctx values — pass it; when it is not used, do not force it, to avoid polluting signatures with meaningless context parameters

## Quality Assurance

- Run **`make lint` before the end of every turn** and ensure it passes; if a lint rule is meaningless for the current code, explicitly disable that rule
- **Predefine constants**: do not hard-code magic values in code logic; keep constants defined in one place
- **Readability first**: if adding logic degrades readability of existing code, prefer refactoring; for large changes, get user consent first

## Impact Surface

- **There are four agent entry modes**: `acp`, `tui`, `channel`, `-p` (runAgent). When changing core agent-loop logic, consider the impact on every entry mode

## Test Safety

- When unit tests need to write local files, **always use `t.TempDir()`**; never write into the user's `~/.tachi` directory

## Integration Tests (itest)

- **Suites under `itest/`**: `itest/run` (run command), `itest/tui` (in-process TUI), `itest/acp` (ACP protocol), `itest/mockllm` (mock LLM server); the run/tui/acp suites depend on mockllm
- **Run via `make itest`** (internally `make -j4` + `ginkgo -p` in parallel); individual suites via `make itest-run` / `itest-tui` / `itest-acp` / `itest-mockllm`
- **`itest/tui` drives the real TUI in-process** (no tmux, no binary build): a real `tui.Model` + real `AIAgent` inside `tea.NewProgram` with injected input/output; keys via `p.Send(tea.KeyPressMsg)`. The renderer's ANSI diff stream is replayed through a self-built virtual terminal (`itest/tui/vt.go`) so `Screen()` returns what a real terminal shows
- **Process-global state in itest/tui**: `config.SetBaseDir` and `tools.SetWorkingDir` are process globals — safe only because ginkgo parallel nodes are separate processes with serial specs; the driver pins a fresh working dir per spec (a stale deleted `t.TempDir` makes Bash fork/exec fail)
- **Shared harness in `itest/harness/`**: `BuildBinary` caches the compiled binary keyed by git HEAD hash under `os.TempDir()/tachi-itest-<hash>`; a dirty workspace falls back to per-call builds, so keep the tree clean before committing
- **mockllm covers three wire protocols** (openai / anthropic / openai-res); a new protocol needs server route + normalize + render + contract tests
- **Tests must stay hermetic**: the harness configYAML template disables `herdr`; never touch the real `~/.tachi`

## Desktop Smoke Verification (demo + mockllm)

- **Scope**: this is how desktop-ONLY paths get verified — the real Wails wiring (bindings, event payloads), the rendered UI, and end-to-end flows. Go unit tests cover logic and `itest` covers the agent core; neither can see whether a binding's result actually reaches a card.
- **Isolate the run**: `HOME=/tmp/<smoke> …/Tachi` redirects `~/.tachi` (`config.BaseDir` follows `os.UserHomeDir`), so sessions, config, `desktop_ui.json` and logs all land in a throwaway dir. That HOME needs a `config.yaml` with a provider: without one `prepareSession` fails and `LoadSession` returns an empty page (empty transcript, no error).
- **Never run the stock bundle while the user's app is running**: `open -a <path>` matches by BUNDLE and `pkill -f "Tachi.app/Contents/MacOS/Tachi"` matches by EXECUTABLE PATH — both hit the user's instance (this has actually fronted and killed it once). Copy the bundle instead — `TachiSmoke.app`, executable renamed `TachiSmoke`, `CFBundleIdentifier`/`Name`/`Executable` rewritten, re-signed ad-hoc (`codesign --force --deep --sign -`) — then `open -a …/TachiSmoke.app` and `pkill -f TachiSmoke` can only touch yours.
- **Fixtures are synthetic sessions**: `$HOME/.tachi/session/<id>/{meta.json,messages.jsonl}`, same shapes as `session.Store` (`type: user/assistant/tool_call/tool_result`, `tool_call_id` pairing, `args` as a JSON OBJECT); bump `updated_at` so the app auto-loads it on launch. Add whatever the feature needs — a `git init` repo with a dirty tree, extra roots in `additional_dirs`, a `desktop_ui.json`.
- **Drive the UI with `TACHI_DEMO=1 TACHI_DEMO_JS=<file>`** (`desktop/demo.go`): the webview content is not in the accessibility tree, so JS injected into the page is the reliable automation path. Patterns: `scrollIntoView` before clicking a card; the composer needs the native value setter + an `input` event (React `onChange`); components using `onMouseDown` (pickers) need `dispatchEvent(new MouseEvent('mousedown'))`.
- **Launch through `open --env`, not the bundle's executable**: `open <bundle> --env HOME=… --env TACHI_DEMO=1 --env TACHI_DEMO_JS=…` passes the env AND hands the window to LaunchServices, so it comes up frontmost (a directly-exec'd binary does not). Two traps: (a) if a previous smoke instance is still alive, `open` just activates it and passes NOTHING — always `pkill -f TachiSmoke`, `sleep`, then assert `pgrep -f TachiSmoke | wc -l` is 0 before opening; (b) a direct exec and an `open`-launched copy can coexist (LaunchServices does not see the former), two instances then share one HOME and write duplicate turns into the same session — confusing when reading the transcript back.
- **Make the screenshot carry the assertions**: install `window.onerror` / `unhandledrejection` handlers and render each step's result into a fixed monospace banner. One `screencapture` then shows the UI AND the pass/fail lines, and a runtime failure (e.g. a Go↔TS field-name mismatch) appears as a red bar instead of silence.
- **Real turns need a scripted LLM**: `itest/mockllm` is an in-process library (no standalone binary), so write a small driver that starts `mockllm.NewServer(mockllm.WithProtocol(mockllm.ProtocolOpenAI))`, scripts `mockllm.Step{Reply: mockllm.Stream(mockllm.ToolCallStart(id, tool, argsJSON), mockllm.Finish("tool_calls"), mockllm.Usage(…), mockllm.Done())}`, prints `BaseURL()` and blocks. Point the smoke `config.yaml` at that URL (openai needs the `/v1` suffix) and set `title_generation: false`, or an unscripted request eats a script step. Narrow a driver to a SINGLE protocol so step accounting stays obvious.
- **Let the mock write the config, and make it dump what it received**: mockllm binds a random port, so hand-editing `config.yaml` between runs cannot work — have the driver write `$HOME/.tachi/config.yaml` from its own `BaseURL()` before it serves. While it is there, have it also write every recorded request (`mock.Requests()` → messages) to a file: that turns "the UI looks right" into "this is the exact prompt that reached the model", which is the strongest evidence a frontend-assembled message is correct (a rendered bubble can be right while the payload is wrong).
- **Start the mock in the SAME shell invocation as the run**: a background process started by a finished tool call gets reaped, and the app then fails with `connection refused`. Launch + drive + capture + kill belong in one command.
- **Capture**: `screencapture -x -R x,y,w,h` (coordinates are logical points). `screencapture -l <windowid>` returns a blank frame for an occluded window — WebKit does not composite a window nobody can see — so front the instance once and capture a region. A region shot silently returns whatever window is there: confirm from the titlebar / session id that the screenshot is YOUR instance.
- **What it does not prove**: real provider behaviour (mockllm is protocol-shaped but synthetic), model quality, human feel/perf. Native dialogs (folder pickers) cannot be driven this way — cover those with Go-level tests.

## Edge Cases

- When modifying **one-off paths**, account for the **no-session** case (e.g. TUI just started, running a one-off command directly)

## GitHub Workflows (CI/CD)

- **Workflows under `.github/workflows/`**: `ci.yml` (push/PR to `main` → `test` / `build` / `integration` jobs), `release.yml` (tag `v*` → goos/goarch matrix build + `action-gh-release`); shared steps live in composite actions under `.github/actions/`
- **Frontend must be built before any Go compile**: `web/frontend/dist` is gitignored yet embedded via `web/frontend/embed.go` (`//go:embed dist`), so a fresh checkout fails every Go compile (`pattern dist: no matching files found`). CI runs `.github/actions/web-build` (setup-node 20 + `npm ci` + `npm run build`) in each job before touching Go
- **Watch out when editing workflows**: `go test ./...` compiles the `web/frontend` package, and the itest harness (`itest/harness.BuildBinary`) does a raw `go build .` — both need `dist/` present
- **Node toolchain**: vite 5 requires Node `^18.0.0 || >=20.0.0`; CI pins Node 20, and `npm ci` requires `package-lock.json` to stay in sync (don't leave an out-of-sync lockfile)

## Web Console (Frontend)

- **Frontend lives in `web/frontend/`** (React 18 + Vite 5 + TypeScript + Tailwind); the HTTP server is `web/server.go` + `web/api.go` (`tachi web` command)
- **`web/frontend/embed.go` embeds `web/frontend/dist`** into the Go binary via `//go:embed dist` (served under a `dist` prefix via `fs.Sub`); the dist tree is gitignored — never commit build output
- **Build flows**: `make build` always runs `web-build` (`npm install && npm run build`); `make web-check` builds only when `dist/index.html` is missing (cheap for local `make test` / `make itest` on a fresh checkout); CI uses the composite action instead
